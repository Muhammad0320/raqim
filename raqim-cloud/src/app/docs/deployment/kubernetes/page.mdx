# Altitude 3: The Deployment Plane

The execution layer for Raqim OS. This document outlines the physical deployment architecture for Sovereign Bare-Metal clusters.

<K8sTopologyDiagram />

## The Sovereign Philosophy

Raqim is not a stateless web application; it is a **Database Operating System**. 

Deploying Raqim requires abandoning traditional, ephemeral cloud paradigms. We strictly mandate bare-metal Kubernetes (K3s or RKE2) deployments. By operating at the bare-metal layer, we strip away the abstraction penalties of managed control planes, allowing the Raqim OS hypervisor to directly bind to physical hardware interrupts and memory allocations. We treat the cluster not as a server farm, but as a singular, distributed supercomputer.

## The Distroless Armor

Every node boots from a 40MB scratch binary. There is no package manager, no /bin/bash, and no glibc overhead. The attack surface is mathematically minimized.

By enforcing a pure distroless architecture, we achieve a near-zero threat boundary. The resulting container configuration means that even if remote code execution occurs at the WASM layer, there is literally no shell or utility library to pivot into. The operating system is the binary, and the binary is immutable.

## Data Gravity & StatefulSets

Raqim is a Database OS. Standard K8s Deployments destroy data gravity. We enforce StatefulSets to guarantee stable DNS resolution (raqim-0.raqim-headless.svc.cluster.local) and strict binding to local NVMe Persistent Volumes (PVCs).

If `raqim-0` experiences a hardware fault, the scheduler is forced to mount the exact same physical block storage unit upon restart. This volume anchors the Write-Ahead Log (WAL) and index structures, avoiding slow, network-bound replication by anchoring execution direct to local storage.

## The Headless Mesh

Standard K8s Services inject iptables or IPVS overhead. Raqim bypasses this using a Headless Service (ClusterIP: None), allowing the Zenoh mesh to map the exact physical IP of every peer pod for direct TCP handshakes.

This bypasses virtual load balancer IP allocations and iptables routing loops. CORE DNS resolves individual, stable records directly pointing to the real interface IP addresses (e.g. `raqim-0.raqim-headless.raqim-system.svc.cluster.local`), establishing pure, low-level point-to-point TCP tunnels between swarm nodes.
